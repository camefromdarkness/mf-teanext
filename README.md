# MOON FLOWER

Магазин китайского чая на Next.js с каталогом в PostgreSQL и админ-панелью.

## Первый запуск

1. Создайте PostgreSQL-базу данных.
2. Скопируйте `.env.example` в `.env.local` и задайте `DATABASE_URL`, `AUTH_SECRET` и ключи используемых OAuth-провайдеров. `SUPER_ADMIN_TELEGRAM_IDS` — список числовых Telegram ID супер-администраторов через запятую; если оставить переменную пустой, автоматическое назначение супер-администратора отключено.
3. Установите зависимости и примените схему с начальными товарами:

```bash
npm install
npm run db:generate
npm run db:deploy
npm run db:seed
npm run dev
```

Фотографии из `public/images/` переносятся в каталог автоматически. Новые загрузки сохраняются в `public/uploads/teas/` и отдаются отдельным маршрутом, чтобы они сразу открывались без пересборки Next.js; при размещении на VPS сохраняйте этот каталог или подключённый Docker volume. Неиспользуемые загруженные фото можно удалить из библиотеки изображений в админ-панели (кнопка удаления доступна администраторам); фотографии, связанные с товарами, сначала нужно убрать из их карточек. На отдельном production-сервере загрузки не появятся автоматически — для них нужен перенос Docker volume или каталогов.

Переход в админ-панель `/admin` доступен из личного кабинета сотрудникам. Супер-администратор и администратор видят таблицу пользователей и заказы; администратор назначает менеджеров, супер-администратор также назначает и снимает роли администраторов. Менеджеры могут добавлять товары и менять их порядок, просматривать заказы, подтверждать оплату или отклонять заказ. История заказов загружается постранично по 30 записей, за один запрос обновляются статусы не более 10 ожидающих заказов из МойСклад. Заказ покупателя резервирует остатки при создании. При подтверждении оплаты резерв сохраняется до фактической отгрузки: для этого используется обычный статус заказа МойСклад. При отмене сайт снимает резерв и устанавливает неуспешный статус, возвращая товар в доступный остаток. В панели для этих действий доступны только статусы соответствующего типа. Администраторы также могут удалять локальные записи истории заказов: документы МойСклад и данные склада при этом не удаляются. Менеджеры не могут изменять существующие товары, управлять пользователями или удалять историю.

В личном кабинете `/account` покупатель может изменить имя, указать телефон для связи, скопировать свой UUID и просмотреть последние 30 заказов. Telegram-вход не передаёт сайту телефон автоматически — покупатель указывает его в личном кабинете. Для оформления заказа всегда требуется вход через один из настроенных социальных провайдеров и номер телефона в профиле. Корзина автоматически показывает телефон из личного кабинета; заказ привязывается к аккаунту. Сайт сохраняет состав заказа и актуальные цены из каталога, после чего покупатель должен отправить подготовленное сообщение магазину в Telegram. До подтверждения магазином заказ отображается как ожидающий подтверждения.

Каталог и цены задаются на сайте. Перед сохранением позиции в админке требуется связать её с соответствующим товаром МойСклад; доступное количество рассчитывается из отчёта остатков выбранного склада за вычетом резерва. Корзина не позволяет выбрать больше доступного количества, а сервер повторно проверяет остаток при оформлении. Заказ покупателя создаётся в МойСклад по цене сайта. Ссылка для отправки заказа в Telegram остаётся частью оформления и появляется только после успешной записи заказа в МойСклад.

Для локальной разработки задайте `MOYSKLAD_TOKEN`, `MOYSKLAD_ORGANIZATION_ID` и `MOYSKLAD_STORE_ID` в `.env.local`; для VPS — в `.env.staging`. Токен создаётся в настройках API МойСклад. Не отправляйте его в чат и не сохраняйте в Git.

## SEO

Главная страница включает заголовок, описание, canonical URL, Open Graph, Twitter Cards и локаль `ru`. Маршруты личного кабинета, входа и админ-панели помечены `noindex`; API закрыты от обхода в `robots.txt`. `sitemap.xml` содержит главную страницу.

Чтобы разрешить индексацию боевого сайта, задайте `SITE_URL` в его файле окружения как публичный HTTPS-адрес, например `https://example.com`, затем пересоберите приложение: `SITE_URL` используется при сборке метаданных. Не задавайте `SITE_URL` для стейджинга: без него сайт автоматически помечен как `noindex`, а карта сайта не публикуется для индексации.

## Структура

- `app/` — маршрут главной страницы, метаданные и общие стили.
- `components/` — шапка, каталог, карточки чая, фильтры, корзина и подвал.
- `app/account/` и `app/api/orders/` — личный кабинет, профиль и история заказов.
- `data/tea-seed.ts` — исходный список для начального переноса каталога в базу.
- `prisma/` — схема PostgreSQL, миграции и seed-скрипт.
- `public/images/` — фотографии товаров; изображения доступны по адресам `/images/<имя-файла>`.
- `public/uploads/teas/` — загруженные через админ-панель фотографии (не включаются в Git).

Корзина хранится в браузере пользователя.

## Развёртывание стейджинга на VPS через Docker

Понадобятся VPS с Docker Engine и Docker Compose, домен с DNS-записью на VPS и доступными извне портами 80 и 443. В Compose уже включён Caddy: он автоматически получает и обновляет HTTPS-сертификат и проксирует запросы к приложению. Отдельно устанавливать Nginx/Caddy на VPS не нужно. Если серверный firewall или панель хостинга фильтруют трафик, разрешите входящие TCP-порты 80 и 443 (и UDP 443 для HTTP/3). PostgreSQL не публикуется наружу.

1. Получите исходники проекта на VPS (например, клонируйте репозиторий) и перейдите в каталог `mf-tea`.
2. Создайте серверный файл настроек:

   ```bash
   cp .env.staging.example .env.staging
   chmod 600 .env.staging
   ```

3. Создайте A-запись (и при использовании IPv6 — корректную AAAA-запись) домена `STAGE_DOMAIN` на IP VPS. Дождитесь применения DNS. Отредактируйте `.env.staging`: задайте `STAGE_DOMAIN` без `https://`, например `stage.example.com`, а `AUTH_URL` с протоколом, например `https://stage.example.com`. Также задайте пароль БД, `AUTH_SECRET`, `SUPER_ADMIN_TELEGRAM_IDS` и ключи провайдеров входа. Для Telegram Login переменные `AUTH_TELEGRAM_ID` и `AUTH_TELEGRAM_SECRET` — это Client ID и Client Secret из BotFather → Login Widget, не `@username` бота и не Bot API token. Для `POSTGRES_PASSWORD` используйте случайную hex-строку, чтобы не было проблем со специальными символами в URL подключения. Секреты не помещайте в Git.
4. Соберите приложение и примените миграции:

   ```bash
   docker compose --env-file .env.staging build app
   docker compose --env-file .env.staging build migrate
   docker compose --env-file .env.staging run --rm migrate
   docker compose --env-file .env.staging run --rm migrate npm run db:seed
   ```

5. Запустите сервисы:

   ```bash
   docker compose --env-file .env.staging up -d
   docker compose --env-file .env.staging ps
   ```

   Первый запуск также загрузит существующий каталог из seed-скрипта. Повторный запуск seed безопасен для уже добавленных или отредактированных товаров.

При последующих обновлениях проекта выполните сборку приложения, примените миграции (`docker compose --env-file .env.staging run --rm migrate`) и перезапустите сервисы (`docker compose --env-file .env.staging up -d`). Именованные Docker volumes `postgres_data`, `tea_uploads` и `caddy_data` сохраняют базу, загруженные через админку фото и данные HTTPS-сертификатов между пересозданиями контейнеров. Не используйте `docker compose down -v`, если не хотите удалить эти данные. Перед обновлениями VPS рекомендуется настроить резервное копирование PostgreSQL и пользовательских файлов.
